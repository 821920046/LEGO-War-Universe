# Google Flow / Veo 3 — 最佳实践

本页汇总针对 Google Flow（底层模型 Veo 3）的实操规则，所有 Prompt 与模板都以此为依据。

## 基础参数

- **时长**：每个镜头固定 **8 秒**（Flow 提供 4s / 6s / 8s）。更长的视频通过 Flow 的「延伸 / 场景构建（Extend / Scene Builder）」把多个 ~7–8 秒片段串联，最多约 20 段。
- **分辨率 / 帧率**：720p、24fps；比例 16:9（横屏）或 9:16（竖屏）。
- **模型**：使用 **Veo 3**（支持原生音频与对白）。

## Prompt 结构（推荐顺序）

把 Prompt 当成「只描述本镜头所见」的超短剧本，按以下顺序组织：

```
镜头/运镜 → 主体 → 动作 → 场景 → 光线 → 风格 → 色调 → 音频 → (对白)
```

- 长度约 **3–6 句、100–150 词**，作为一个自包含的单一镜头。
- **运镜与主体动作分开写**：先说相机怎么动，再说主体怎么动。
- 动作要能在 **8 秒内自然完成**，不要塞多个大事件。

## 语言与措辞

- **用英文写 Prompt**：Veo 对英文理解最佳（本项目所有资产文字均为英文）。
- **正面描述**该出现什么，负面内容单独放进 Negative Prompt。
- **避免时间/顺序词**（now、then、after that、continues…）出现在正文里 —— 单镜头是一个瞬间的连续动作，不是分段叙事。镜头衔接靠 Continuation 句和分镜结构，而不是靠这些词。
- 具体优于笼统：`dark tan weathered bricks` 好过 `a tank`。

## 音频与对白（Veo 3 原生支持）

- 用 `Audio:` 描述环境声/音效（引擎、爆炸、风、无线电）。
- 对白放在引号内，且**足够短**以适应 8 秒，否则可能说不完或不发声。
- 一个 8 秒镜头建议最多一句短对白。

## 一致性策略（长片关键）

1. **资产逐字复用**：同一角色/载具的描述文字一个字都不改（本项目用 `assets.json` 强制统一）。
2. **统一风格块**：每个 Prompt 都带同一段 Style。
3. **统一负面约束**：每个 Prompt 都带同一段 Negative。
4. **统一色彩包**：全片用同一 Color Grade，避免镜头间色调跳变。
5. **镜头衔接**：用动作接力（上一镜结束动作 = 下一镜起始动作），而不是重开新事件。

## 生成失败时的修正策略

| 问题 | 修正 |
|---|---|
| 人物/载具走形、比例怪 | 强化资产描述里的 `same proportions / consistent scale`，减少同框主体数量 |
| 出现多余角色/重复载具 | 检查 Negative 是否包含 `no extra characters / no duplicated vehicles`，动作句只描述一个主体 |
| 塑料感不足、不像乐高 | 保留 `photorealistic LEGO plastic, real brick textures`，避免加入写实人物词 |
| 动作没发生或太乱 | 一个镜头只留一个核心动作；把次要动作拆到下一个 S 镜头 |
| 色调忽明忽暗 | 固定同一 `CLR-` 色彩包与 `LGT-` 灯光包 |
| 对白没声音 | 缩短对白，确保能在 8 秒内说完 |
| 出现字幕/水印 | Negative 保留 `no subtitles, no captions, no watermark, no logos` |
