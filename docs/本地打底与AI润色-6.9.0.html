"我需要有智能功能，依靠本地加AI，使得脚本内容更真实，更完美，当AI模型不可用时自动切回本地。"

〇、旧架构：AI 优先，失败才整部落本地

6.9.0 之前，云端 AI 与本地引擎是二选一：AI 可用时，整部分镜——包括资产 ID、镜头结构、台词——都由模型自由生成；AI 不可用时才整部落回本地。这个架构有两个后果，都不是「偶发失误」，是结构决定的：

后果 ① 幻觉面覆盖整部电影

模型自由生成结构，于是资产 ID 会编（6.8.8 治过）、导演会编（6.8.9 治过）。两轮治的都是同一棵树上结的果：AI 同时拥有「写什么」和「怎么写」的权力。

后果 ② 模型过载时用户白等

线上实测过 503 风暴：三个 Gemini 候选全挂。旧路径下每次请求把所有候选再撞一遍，用户等几十秒，拿到的是本地引擎毫秒级就能给出的东西——基底本来就在本地手里，却要先问过云端才给。

于是幻觉面从「整部电影」塌缩到「三句文案」，而这三句再被代号守卫与字段白名单焊死。AI 的创造力全部释放在「这句话怎么写才有电影感」，而不是「这一镜用什么资产」——后者本地有 810 项真实资产和时代门控，本来就比模型稳。

自由战术分镜模式同样接入：前端本地出基底（mode:'plan' 发来），后端只做润色这一件事，两边不重复实现对方的核心能力。

二、合并层的四条不变式

不变式实现防住什么
① 结构永不由 AI 提供合并以「展开基底对象再覆盖三个文本字段」实现，其余字段静默丢弃模型自创镜头、自改 phase/subjects/资产 ID
② 未提供/空字段保留基底原文没提这个字段 = 不算拒绝、不动基底「润色失败一镜」被误读成「这一镜没了」
③ 代号守卫润色文本出现名册外【代号】→ 整字段拒绝并记账台词称呼与定妆表漂移（下游 script-callsign 契约要求台词代号必须来自名册）
④ 一切拒绝都记账merged / kept / rejected 进响应体，不是内部日志静默吞掉拒绝 = 把「AI 没润成」显示成「润色成功」

混合数组的位置落地禁令：AI 条目有的带 shotId、有的不带时，无 ID 条目一律拒绝、不猜位置——猜错会把 B 镜文案贴到 A 镜上（文本错镜比不润色更糟）；只有整数组都不带 ID 时才按数组位置落地。

三、熔断器：让失败路径也快

每 provider 连续失败 3 次开闸、60 秒冷却、到期半开放行一次、成功即关闸归零；now 时钟探针注入，窗口轮转不必真等。冒烟实测（mock 503 风暴）：

503 风暴下的两次请求（实测）
第 1 次请求：3 个 gemini 候选全试（=3 次连续失败）→ 开闸
  reason=ALL_PROVIDERS_FAILED，交付本地基底

第 2 次请求：云端调用 0 次，约 200ms 出完整片
  reason=CIRCUIT_OPEN，breakerSkipped=['gemini']

熔断跳过本身不记失败（不能拿熔断自己的跳过延续熔断），只如实记账进 aiStatus.breakerSkipped。Workers 的模块级状态是 isolate 内尽力而为——是优化，不是正确性依赖：丢了最坏只是多试一次。

四、两处靠测量才定得下来的设计

敌方登场守卫必须前移到 AI 之前

实测本地规划器对「现代特战城市巷战」产出的名册敌方为 0。结构冻结之后 AI 没机会补——所以 ensureOpposingPresence 作用在基底上。测完之后才把守卫写进基底阶段，顺序反了就会 silently 回归。

润色路径绝不走 alignShotsToLego

实测它会剥掉基底的富结构字段（beatId/fn/focus/duration/fx/audio/story）。润色链只走 diversifyShots + tagDramaticFunctions（两者 spread 保字段）——否则「结构冻结」会在合并后被自己人破坏。

五、元数据：双可信来源，recognized:false 换了语义

影片元数据只可能来自两个地方：① 手写策展库的影片事实（Strategy：绝不拿手写库的事实去问 AI——问就等于把事实陈述降级成模型回忆，平白制造幻觉面）；② 模型对「它确切知道的真实影片」的回答。

6.9.0 起 recognized:false 的语义从「作废这次调用」变为「元数据留空、润色照常」：本地基底已在手，模型只改三句文案，没有理由把一次成功的润色扔掉。此时 aiStatus.reason=OK + unrecognized:true 透明标记（前端提示「未识别为已知影片，元数据已留空」）。新增 reason：CIRCUIT_OPEN、POLISH_REJECTED（云端返回了但一字段都没过守卫——必须与「润色成功」和「全部失败」都区分开）。

七、边界与未竟事项

· 幻觉面只是塌缩到三句文案，没有归零：action 里仍可能出现与现实世界不符的描写（治理引擎继续兜底）；模型是否持续听话只能靠线上复测维持，措辞保持「本次未复现」而非「已根除」。
· 熔断状态是 isolate 内尽力而为，Workers 多 isolate 不共享——最坏多试一次，不影响正确性。
· 发布后线上复测承诺（与 6.8.9 同样的纪律）：自编片名应走「本地基底 + 润色」、徽章含润色与未识别标注；503/断 Key 场景验证熔断与快速回退。
· 遗留运维项（需用户操作）：OpenRouter 变量线上 configured=false（重新保存 + Redeploy）；Groq Key 403（控制台重生）；OpenRouter 8 候选裁 4（等本地基准）。
· 本项目产出文本 prompt，从未调用 Veo 3 / Flow——这条边界不变。
