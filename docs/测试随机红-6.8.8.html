测试套件随机红：四个根因，而不是我以为的那一个

LEGO War Universe · 2026-10-16 · npm test 6 次连跑挂 3 次 → 逐个确定性实验钉死 → 修复并反向验证 → 323/323、连跑 3 次全绿

"我把随机失败归成了单一根因（并行写 375KB 生成文件），修完发现还有两个。症状不同就不能共用一个解释 —— 这一轮的全部价值就在于没有把「想当然」当结论。"

〇、现象：三种互不相同的死法

6 次连跑全量测试，3 次出现 # fail 1。三次失败的症状完全不同，这本身就是"不止一个根因"的第一个信号：

另外，本轮开始前还单独抓到过一次整文件级失败（character-lineup.test.mjs，SyntaxError: The requested module './assets-data.js' does not provide an export named 'assets'）—— 它和我最初认定的根因对应，但解释不了 A/B/C 任何一个。一个根因解释三类症状，说明根因不止一个。

一、根因 A：5 个测试文件共用一个限流桶

/api/ai-brain 的限流是 30 次/60s 滑动窗口；不带 cf-connecting-ip 的调用，客户端标识一律退化成 'anonymous' —— 全套队所有这样的调用共用一个桶。

定位实验（确定性复现）

35 次不带 cf-connecting-ip 的连续调用（fetch 已桩掉，无外网）
#31 status=429 aiStatus缺失=true body={"error":"RATE_LIMITED","retryAfterMs":51026}
#32 status=429 aiStatus缺失=true ...
#33 ~ #35 同上
RESULT 35 次调用中 429 共 5 次

429 的响应体里没有 aiStatus / roster —— 于是现场 A 的 data.aiStatus.providers、现场 B 的 data.roster.filter 双双变成 TypeError。是否撞上 429 取决于调用与 60s 窗口的相对时序（窗口一进化计数就重置），所以表现为随机而非必现。

修复与验证

修复

三个 /api/ai-brain 测试文件的 helper 每次调用换一个独立客户端 IP（每次调用仍是一个独立客户端，独立计数，限流没有被关掉）。

正面验证

同脚本换成唯一 IP：35 次调用 429/异常共 0 次。

契约门禁

新增 tests/rate-limit-contract.test.mjs：两个端点限流器各 4 条（30 次放行/第 31 次限流、按客户端隔离、窗口轮转重置、窗口内不误限）+ handler 级 1 条。

给 checkRateLimit 加了 now 时钟探针：窗口轮转（60s）在测试里不可能真等，没有探针这条行为就不可测。此前限流器一条契约测试都没有。

/api/compose 的桶在 disabled 模式下恒为 'development'，两个测试文件调用量远低于限额（6 次连跑从未因它红），只在文件头加共享桶警示注释，不虚改动。

二、根因 B：测试在并行跑时非原子重写 375KB 生成文件

tests/build-assets.test.mjs 调 buildAssets({ root })（write 默认 true）。npm test 并行跑多个测试进程时，它非原子重写 src/domain/assets-data.js（375KB），别的进程正好 import 到写一半的文件 → 整文件 SyntaxError。

两层修复

① 测试只读不写

改为校验仓库里真正提交的产物与源一致。旧测试"先重写再比对"—— 产物永远新鲜，永远抓不到漂移，是个恒绿的门禁。

② 生成器原子写

临时文件 + rename。竞态演示（4 读者 × 500 次 import）：非原子 约 44% 读失败，原子 rename 0%。

Windows 上的意外：rename 会崩

第一轮原子写演示：writer 直接被 rename 炸掉
Error: EPERM: operation not permitted, rename
  '..._race_target.tmp-9340' -> '..._race_target.js'
  at async file:///.../_race_writer.mjs:22:5

Windows 上 rename 不能覆盖"正被其他进程打开"的目标文件。也就是说，只做 POSIX 式原子写在 Windows 本地会引入新的失败模式：构建本身失败。最终形态：rename 失败时回退直接写 —— 最多退化成非原子（有竞态窗口），但构建不会因为"恰好有读者"而失败。失败可以降级，不能把降级藏成异常。复测：writer 400 轮全部完成、readers 2000/2000 全 ok、零 EPERM。

演示工具的自我纠正（值得单独记）

第一版演示脚本的 full 内容是 'export const value = 1;\n'.repeat(50) —— 50 个同名 const，本身就是非法模块。 readers 报的 417/500 失败几乎全是 Identifier 'value' has already been declared，跟竞态毫无关系。判定"失败了什么"之前，必须先证明失败来自被测机制：修正内容为 50 个唯一声明，并加无 writer 预检（100/100 ok），两次竞态模式的数据才可信。

三、根因 C：超时测试的 200ms 预算，比它要保护的本地工作还慢

现场 C 与 A/B 不同型：请求成功了，但 aiStatus.timedOut 是 false。该测试设 AI_PROVIDER_TIMEOUT_MS=40 + AI_REQUEST_BUDGET_MS=200，配挂着不回的 fetch。

定位实验（8 路并行负载）

预算结果读法
200ms8 路里 5 路：三次候选全部 skipped、一次都没发出去，timedOut=false从请求启动到第一次模型调用之间的本地工作（治理/意图/资产目录组装）空闲约 63ms，负载下超过 200ms —— 预算在第一次调用前就被耗尽
5000ms8 路全部 timedOut=true、3 次真超时、零 skipped预算的职责是兜住整次请求，不是"比本地准备更快"

测试的 elapsed < 5000 断言也一并放宽到 15000：总预算 5000 + 一次在途超时 40 + 本地兜底与响应组装的余量，原断言比预算语义本身还紧。

四、根因 D：毫秒遥测数字被 LEET 归一化误判成恐怖组织词

前三个根因修完、连跑 3 次验证时，第 1 次又挂了一个从未见过的用例（502）。502 只能来自 governResponse 的 GENERATED_CONTENT_BLOCKED 分支，而 query 与复刻内容全是确定的 —— 唯一变量是响应体里的毫秒遥测数字。

机制：治理扫描的是整个响应体 JSON，而 LEET 归一化 '1'→i / '5'→s / '0'→o 无差别作用在所有词元上。latencyMs: 1515 被归一成 "isis" → 整条响应判 EXTREMISM_AND_TERROR → 502。

扫描 1..99999（响应体真实形态 JSON.stringify）
误判为 blocked 的数字共 16 个：
  149, 150, 151, 1511, 1512, 1513, 1514, 1515,
  15133, 15134, 15135, 15151, 15152, 15153, 15154, 15155
全部落在「合法生成的常见耗时」区间内。

用户视角：「同样的输入，有时莫名其妙被拦截」。测试视角：随机红。这是四个根因里唯一一个**线上级产品 bug**（前三个是测试基建问题），且它是在"连跑验证"时才暴露的 —— 如果只跑一次全绿就收工，它会带着上线。

修复

纯数字词元跳过 LEET 归一化：扫 1..99999 误判 16 → 0。

强度不降

混合形态 i5i5 / 1s1s / put1n / i s i s 仍全部 blocked。

门禁

遥测数字全量扫描 1..99999 一条 + 混合形态仍拦截一条；反向验证：改坏修复 → 门禁精确报出「遥测数字 149 被误判」。

五、站点图标（用户需求）

新增 public/favicon.svg（矢量版：LEGO 砖块剪影 + 项目识别色琥珀）、public/apple-touch-icon.png（180px）、public/favicon-32.png（32px）；index.html 挂三个 <link> + theme-color。此前前端一个图标引用都没有。index.html 的 diff 经验证只有图标相关改动。

LEGO War Universe · 6.8.8 · 元教训：① 症状不同就不能共用同一个解释 —— 四个根因四种死法，「都想通了」往往是只通了一个；② 修完必须连跑：第四个根因是在连跑验证时才暴露的，单次全绿会让它带着上线；③ 验证工具本身也要被验证（本轮演示脚本两次先骗过我）；④ 恒绿的门禁比没有门禁更危险（旧 build-assets 测试就是）；⑤ 遥测字段不是内容 —— 治理扫描全字段 JSON 时，必须想到「什么时候的数字会被归一化命中」。
