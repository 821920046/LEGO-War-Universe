LEGO War Universe · v6.7.3

画面语言：把「编译后的 prompt」当成交付物来读

用户诉求：「内容方面还是需要优化，还是不够完美，请继续在脚本内容上下功夫，让这些脚本生成的视频内容更加完美。」

前六轮我一直在读 action（中文叙事正文）—— 而真正送进 Veo 3 / Google Flow 的是 compileShot() 编译出来的 prompt，里面有场景、主体、动作，也有机位、灯光、调色、音效。这一轮第一次把编译结果整条打印出来读，读出了本项目迄今最严重的一批缺陷：叙事正文是对的，编译出来的 prompt 是错的。资产 806 → 810，构建签名 5fcb1b870ef4 → 2a778c168cbc，测试 231 → 246。

一、七项修复概览

① 39 个机位里 36 个是死代码

「滩头低角度推进跟拍」跨 10 个题材被用了 48 次；二战只有 1 个时代专属机位，于是二战影片只拿到 1 个机位。

② 夏季正午的草原配「夜空」光照

库尔斯克（夏季硬光白昼）拿到「战火映照的夜空」；灯光同样只用 1–3 个。

③ 216/216 个镜头同一个调色

全是「好莱坞大片」。5 个调色资产里 4 个是死代码。修好「只用 1 个」后又露出选不准（见第三节）。

④ 4 秒的快切里装着 8 秒的叙事

4 秒镜平均 64 字 / 3.6 个分句（最长 76 字 / 5 句），而 6 秒镜与 8 秒镜都只有 55 字。

⑤ 音效与无线电对白从未进入 prompt

audioCue 与 radioVoice 在 180/180 个镜头里都有值，编译出的 prompt 里一个声音字都没有。Veo 3 是带音频生成的模型。

⑥ 关键帧 prompt 塞了整段叙事

Framing & Pose 直接塞入完整中文叙事，而 toStaticPose() 只处理英文动名词；还会输出 交战。.

⑦ 因果连接词是拍不到的旁白

「压力还在加码，」「计划定下了，」—— 这正是喂给模型的第一个分句，模型既画不出「压力」也听不出「加码」。

⑧ 时段只识别「夜」

「海湾战争夜战防空导弹阵地伏击」判不出夜间；「黄金时刻」「拂晓登陆」全部落空。

二、根因：一个「看起来在工作」的死函数

机位、灯光、调色此前共用同一个选取函数。它有两处错叠加：

修复前 · planner.js
const pickMany = (r, kind, intent, limit = 3) => {
  const eraMatches = all.filter(a => a.series === intent.era);
  const pool = eraMatches.length > 0 ? eraMatches : all;
  return pool.slice(0, limit);   // ← 取数组前三个
};
修复后 · visual-language.js（新增 260 行）
poolFor()      // 并集：时代相容 ∪ 全部
selectCameras() // 域 + 时段 + 地貌三级过滤
selectLightings()// 全片一盏主光
selectColorGrade()// 三档域 + 场景 + 关键词
// pickMany 已整个删除
错后果
eraMatches 是替换而不是并集二战只有 1 个时代专属机位 → 二战影片只拿到 1 个机位。时代专属资产应该是加分项，不是全部候选。
slice(0, limit) 不判域、不判时段39 个机位里 36 个是死代码；「滩头低角度推进跟拍」被用在滩头以外的所有题材上。

第四次「关键词骗人」

森林正则里写了裸的 林，于是「斯大林格勒废墟」被判成丛林，城市巷战拿到丛林斑驳光。这与前三次（\bcrew\b、「战斗工兵」、marine）是同一类「用子串匹配语义」的错误。改为只认真正的植被词：

丛林|森林|树林|密林|林地|林区|雨林|jungle|forest|woodland|treeline

打分档权重理由
战场域命中 +2 / any +1 / 不符 0必须是三档。二档时「any」与「地面专用」同分，中性调色就赢不了错误的专用调色 —— 轨道题材因此拿到《黑鹰坠落》。
场景+1调色新增 setting 标注（滩头海面 / 空域 / 城市沙漠 / 开阔林地雪原）。这是区分「同为 ground 的《黑鹰坠落》与《兄弟连》」的唯一依据。
关键词词元命中数只在题材串上数调色自己声明的关键词，不再在环境正文的长英文上跑 LCS。可解释、可回归。

十三、残余风险（如实记录，本轮未解决）

节奏仍然轻微倒挂：climax 7.92s > build 7.56s > establish 7.49s > resolve 6.79s。根因是 narrative.js 给结构节拍 6–8s 的底时长，内容一多就继续往上顶；且 cost 节拍在 12 镜节奏里根本不会被选中，所以它被压到 4s 没有产生实际效果（4 秒档因此在本轮完全未被使用：6s×87、8s×225）。本轮选择不去靠删内容来追这个数字 —— 内容完整优先于时长曲线好看。留待下一轮从 narrative.js 的结构节拍时长分配入手。
